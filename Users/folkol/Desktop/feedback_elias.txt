### __init__

- mode 'r' är default, och behöver inte anges explicit. Se: https://docs.python.org/3/library/functions.html#open
- Istället för open och sedan en close så kan man använda sig av en Context Manager som gör close automatiskt, se: https://www.python.org/dev/peps/pep-0343/#motivation-and-summary.
- str.split har ett andra argument som heter "maxsplit", det behöver man inte ange ifall man vill splitta allt.
- Listor av ord som t.ex. keywords_total kan ofta vara lättare att läsa ifall man formaterar dem så här:
keywords_total = [
    'summa',
    'total',
    'att betala',
    'at betala',
    'totalt',
    'totalt:',
    'subtotal',
    'kontant',
    'belopp',
    'pris',
    'totalt sek',
    'total sek',
    'totalt (sek):',
    'sek',
    'duo/fam enkel'
]
- Att konstruera en lista genom att lägga till allt från andra listor kan göras lite mer elegant med .extend eller med "unpacking":

keys = []
keys.extend(keywords_total)
keys.extend(keywords_moms_percent)
...

keys = [*keywords_total, *keywords_moms_percent, ...]
- "pass" behövs bara i annars tomma kodblock. Finns det något annat i kodblocket så gör den ingen nytta.
- en "placeholder" brukar vara en temporär sak som är tänkt att bytas ut, i det här fallet så verkar det snarare vara "en plats att lägga saker i". Detta brukar snarare callas "accumulator" eller "container".
- Smått förvirrande loop som anropar fill_in_the_blanks. Inte helt uppenbart från __init__ varför den behöver loopa en gång per placeholder.
- Lite ovanligt att man har en lista av listor, som man sedan explicit refererar till de inre listorna på (t.ex. när du printar placeholder[1] etc). Jämför print('total:', placeholders[0]) med print('total:', total).
- Förvirrande API när en funktion tar listor som den ska populera. (Speciellt om den inte heter "populate list" eller liknande). Jag hade gjort ett annat API som t.ex. hade returnerat listan eller dylikt.
- fill_in_the_blanks returnerar något, men det fångas aldrig.
